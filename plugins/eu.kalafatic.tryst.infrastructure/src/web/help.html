TRYST Help

TRYST is a Java 21 Eclipse RCP / OSGi platform that runs as a professional IDE and as a headless autonomous development server. The IDE and the server share one core: projects, tasks, agents, code reviews, persistence (SQLite) and the embedded HTTP/TCP services.

This page documents the workbench (F1 context help, keyboard shortcuts), the headless CLI and the diagnostics endpoints. It is served from the same embedded HTTP server that hosts the TRYST web client.

Getting Started

Launch the workbench

./tryst

Launch the headless server

./tryst -nosplash -application eu.kalafatic.tryst.application.server

With no command argument on a terminal (TTY) the server starts an interactive REPL (tryst> prompt). Without a TTY it runs as a daemon until stopped.

Open the web interface

Use the menu Tools → Open TRYST Web Interface, or run the CLI command /web to print the live URL (the HTTP port is resolved at runtime and may differ from the default 38080 when a fallback port is allocated).

Submit a task

Use File → New Task…, which opens the web intake form, or create tasks through the Tasks menu and the Studio editor pages.

Open a terminal in the workspace

Use Tools → Open Terminal; in the Navigator and Project Explorer views, the context menus offer Open Terminal for the selected project/repository.

Keyboard Shortcuts

TRYST uses the standard Eclipse 3.x workbench key bindings. No custom TRYST key bindings are defined; the workbench defaults apply, plus one TRYST-specific key:

KeyAction
F1Open TRYST web help for the active view/editor (TRYST-specific)
Ctrl+C / Ctrl+X / Ctrl+VCopy / Cut / Paste
Ctrl+ASelect all
Ctrl+Z / Ctrl+YUndo / Redo
Ctrl+SSave active editor
Alt+Shift+QShow View dialog (Eclipse standard)
Ctrl+Shift+LShow Eclipse key assist (if available)
F1 only reacts to a plain press (no Ctrl/Shift/Alt). The anchor is mapped from the active part id; unknown parts fall back to the generic context section.

Context Help

Pressing F1 (or Help → Context Help) opens this page at the section describing the active view or editor.

Navigator

The TRYST Navigator is the flagship hierarchical view: Servers, Sessions, Tasks (partitioned by lifecycle status), Projects & Repositories, Code Reviews, Users, TEIP/AI integrations, Database tables and System items.

  • Double-click a node to open the matching Studio editor page.
  • Right-click for node menus: copy ids/paths, task lifecycle actions (start/pause/resume/cancel/archive/delete), Git pull, and Open Terminal for projects/repositories.
  • More Actions lists the unified contextual actions (Darwin Family contextual contract) resolved by the registry.

Console

The Console Output view shows live application output. Its context menu offers select all, copy, and clearing actions.

Studio Editor

The TRYST Studio editor hosts the administration pages: Overview Dashboard, Task Execution, Task Management, Task Details, Project Explorer, Git, Build, Test Quality, Code Review, AI Integration, MCP, TEIP Integration, Database, Server Monitoring and Configuration. Select pages via the editor header or by double-clicking Navigator nodes.

Database

The Database page and Database Admin view expose the SQLite database: schema/table browsing and integrity tools. The Database menu provides PRAGMA integrity checks, foreign-key verification, WAL checkpoint and VACUUM.

TEIP

The TEIP menu and TEIP Integration page manage the EVO bridge: status/health checks, available EVO capabilities, task routing and the routing history.

Administration Views

Users & Sessions, User Detail, Session Detail, Tasks & Agents and Audit & Logs administer the platform. The same data is available headless through /api/admin/* (users, sessions, processes, audit).

Embedded Browser

The Embedded Browser view connects automatically to the active runtime endpoint (no hardcoded port) and hosts the TRYST web client inside the workbench. The Server Overview view summarizes the live server state.

CLI Commands

The headless server application (-application eu.kalafatic.tryst.application.server) accepts one-shot commands, runs as a daemon without a TTY, or starts an interactive REPL (tryst>) on a terminal. Slash forms (/status, /help, …) and plain forms are equivalent.

CommandDescription
(no arguments)Start the server and keep serving (REPL on a TTY, daemon otherwise).
help [topic]Print general help or detailed help for one command.
statusStart the server, print the live host/port status, exit 0.
webPrint the live TRYST web interface URL.
terminal [dir]Open a terminal emulator in the workspace (or the given directory); guarded when no emulator exists.
modelsList published AI models (GET /api/models).
sessionsList tasks (GET /api/tasks); TRYST has no public /api/sessions endpoint.
providersList AI providers referenced by the published models (GET /api/models).
config [show]Print the effective configuration; no secrets are printed.
logs [show]Print the TRYST log file location and its last lines.
stopGraceful shutdown of the server running in this session (REPL/daemon).
restartExplains the supported restart procedure (relaunch the process).
startExplains the server start modes.
exitLeave the interactive REPL.
Unknown commands fail with exit code 1 and print the nearest command suggestions. /agents is intentionally not exposed: TRYST has no /api/agents endpoint.

TCP text protocol

The TCP service (default port 38280) speaks a simple line protocol: PING, STATUS, PROJECTS, TASKS, HELP (also /help), QUIT, EXIT.

Diagnostics

Diagnostics are served by the embedded HTTP server at the live runtime endpoint (Tools → Open TRYST Web Interface prints it; Help → Diagnostics opens the status endpoint directly).

EndpointPurpose
GET /api/statusServer status summary (readiness, health components).
GET /api/notifications/streamServer-sent event stream of notifications (supports lastEventId).
GET /api/admin/*Administration: users, sessions, processes, audit (authentication applies outside development mode).
Logs: the TRYST log file lives at ~/.tryst/logs/tryst.log (override with -Dtryst.log.dir=...); the CLI command logs show prints its location and tail.
