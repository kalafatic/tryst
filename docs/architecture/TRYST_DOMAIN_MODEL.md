## 1. Core Domain Aggregate Roots and Entities

All domain models reside in `eu.kalafatic.tryst.domain.model` and adhere to strict object-oriented and DDD principles:
- Primary identity is represented as an immutable UUID `String`.
- State mutation occurs exclusively through meaningful domain methods that validate invariants.
- Timestamps are represented using `java.time.Instant`.
- Invariant violations throw `TrystDomainException`.

### 1.1 Project
- **Responsibility:** Represents a discrete software codebase under development.
- **Fields:**
  - `id`: UUID String
  - `ownerId`: String (references `User.id`)
  - `name`: String (non-blank)
  - `description`: String
  - `location`: Path String
  - `status`: `ProjectStatus` (`ACTIVE`, `INACTIVE`, `ARCHIVED`)
  - `createdAt`, `updatedAt`: Instant
- **Domain Operations:** `activate()`, `deactivate()`, `updateLocation()`.

### 1.2 Workspace
- **Responsibility:** Encapsulates the disk boundary, containment rules, active working directory, and isolated sandbox for tasks and projects.
- **Fields:**
  - `id`: UUID String
  - `rootPath`: Path (normalized)
  - `ownerId`: String (references `User.id`)
  - `taskId`: String (references `Task.id` when allocated for a task)
  - `repositoryUrl`: String
  - `branch`: String
  - `status`: `WorkspaceStatus` (`ALLOCATED`, `INITIALIZING`, `READY`, `ACTIVE`, `WAITING_FOR_REVIEW`, `REWORKING`, `COMPLETED`, `ARCHIVED`, `CLEANUP_PENDING`, `FAILED`)
  - `metadata`: Map<String, String>
  - `createdAt`, `updatedAt`: Instant
- **Domain Operations:** `allocate()`, `initialize()`, `markReady()`, `activate()`, `markWaitingForReview()`, `rework()`, `complete()`, `archive()`, `markCleanupPending()`, `fail()`, `transitionTo()`.

### 1.3 AgentTask
- **Responsibility:** A discrete unit of autonomous software development work requested by a user or planner.
- **Fields:**
  - `id`: UUID String
  - `projectId`: UUID String
  - `sessionId`: UUID String
  - `title`: String (non-blank)
  - `description`: String
  - `status`: `TaskStatus`
  - `priority`: `TaskPriority` (`LOW`, `NORMAL`, `HIGH`, `URGENT`)
  - `agentId`: UUID String
  - `executionResultId`: UUID String
  - `reviewId`: UUID String
  - `createdAt`, `completedAt`: Instant
- **Domain Transitions:**
  - `start()` -> Transitions to `RUNNING`
  - `markWaitingForReview(String reviewId)` -> Transitions to `WAITING_FOR_REVIEW`
  - `markApproved()` -> Transitions to `APPROVED`
  - `markCommitting()` -> Transitions to `COMMITTING`
  - `complete(String resultId)` -> Transitions to `COMPLETED`
  - `fail(String resultId)` -> Transitions to `FAILED`
  - `cancel()` -> Transitions to `CANCELLED`
  - `markRecoveryRequired()` -> Transitions to `RECOVERY_REQUIRED`

### 1.4 CodeReview
- **Responsibility:** Human-in-the-loop review artifact encapsulating git diffs, file modifications, heuristic quality checks, and cryptographic commit authorization gating.
- **Fields:**
  - `id`: UUID String
  - `projectId`: UUID String
  - `taskId`: UUID String
  - `branch`: String
  - `status`: `ReviewStatus` (`PENDING`, `APPROVED`, `REJECTED`, `COMMITTED`)
  - `initialDiff`: String (original diff generated by agent)
  - `effectiveDiff`: String (diff including manual user edits)
  - `contentFingerprint`: SHA-256 hex string of effective diff
  - `approvedFingerprint`: SHA-256 hex string captured at approval
  - `commitHash`: Git commit SHA
  - `approvedBy`, `rejectedBy`: User IDs
  - `rejectionReason`: String
  - `buildStatus`, `testSummary`: String
  - `createdAt`, `updatedAt`: Instant
- **Invariants:**
  - Editing files invalidates any existing approval (`approvedFingerprint` cleared, status returns to `PENDING`).
  - Cannot approve without valid fingerprint.

### 1.5 User and UserSession
- **User:**
  - `id`: UUID String
  - `username`: String (unique)
  - `passwordHash`: Hex string (PBKDF2-HMAC-SHA256)
  - `salt`: Hex string (32 bytes)
  - `role`: `UserRole` (`ADMIN`, `PROJECT_OWNER`, `DEVELOPER`, `REVIEWER`, `USER`)
  - `active`: boolean
  - `locked`: boolean
  - `failedAttempts`: int
- **UserSession:**
  - `id`: UUID String
  - `userId`: UUID String
  - `tokenHash`: SHA-256 hex string of bearer token
  - `clientIp`, `userAgent`: String
  - `expiresAt`, `lastActivity`: Instant
  - `revoked`: boolean

### 1.6 Operational Entities
- `AuditEvent`: Structured log of security-sensitive operations.
- `Notification`: In-app alert dispatched to specific users.
- `TelemetrySnapshot`: Machine performance metrics (CPU, RAM, Disk, Active Tasks).
- `ManagedProcessRecord`: Tracking for background child processes (Maven, Git).
- `GitHubCredential`: User-owned encrypted GitHub credentials at rest (id, userId, githubUsername, encryptedToken, scopes, tokenType, expiresAt).
- `GitHubRepository`: Value record for discovered GitHub repositories (id, fullName, owner, name, isPrivate, defaultBranch, cloneUrl, htmlUrl).
- `GitHubBranch`: Value record for discovered branches (name, commitSha, isProtected).

### 1.7 AI Development Execution Subsystem (`eu.kalafatic.tryst.domain.ai`)
- `AIProvider`: Transport protocol abstraction separating LLM communication (tags, chat, streaming, timeouts) from agent logic.
- `ModelRegistry`: Contract for model lookup, provider registration, and role-filtered publication.
- `ModelSelectionService`: Strategy service to resolve optimal AI models for tasks based on user role and availability.
- `PromptContextBuilder`: Assembles token-budgeted prompts containing repository structure, file snippets, and conventions.
- `TaskAnalyzer`: Analyzes user requests, identifies build systems (Maven/Gradle/npm), source files, and conventions.
- `ImplementationPlanner`: Generates ordered implementation plan steps (`ExecutionPlan`, `PlanStep`).
- `CodeAgent`: Coordinates execution, tool commands, streaming callbacks, timeouts, cancellations, and retries.
- `CodeChangeExecutor`: Executes file modifications strictly bounded within authorized workspace sandboxes and tracks modified files.
- `ResultValidator`: Verifies build compilation and test verification stages with failure classification.
- `AiFailureClassification`: Detailed failure taxonomy (`TIMEOUT`, `CANCELLATION`, `BUILD_FAILURE`, `TEST_FAILURE`, `CONTEXT_LIMIT_EXCEEDED`, `MODEL_UNAVAILABLE`, etc.).

## 2. Repository Contracts (`eu.kalafatic.tryst.domain.repository`)

Domain services depend strictly on repository interfaces, completely insulated from SQL or JDBC:
- `ProjectRepository`: `findById()`, `findAll()`, `findByOwnerId()`, `save()`, `delete()`
- `TaskRepository`: `findById()`, `findAll()`, `findByProjectId()`, `findBySessionId()`, `save()`, `delete()`
- `CodeReviewRepository`: `findById()`, `findByTaskId()`, `findByProjectId()`, `save()`, `delete()`
- `UserRepository`: `findById()`, `findByUsername()`, `findAll()`, `save()`, `delete()`
- `UserSessionRepository`: `findById()`, `findByTokenHash()`, `findByUserId()`, `save()`, `delete()`
- `UnitOfWork`: Demarcates transactional boundaries (`runInTransaction`, `supplyInTransaction`).
